網站如何運作：從 HTML 到 GitHub Pages

從你點開一個網址開始，了解瀏覽器、HTML、CSS、JavaScript 與 GitHub Pages 如何合作，並拆解 CodeBase 本身的結構。

🎯 學完你可以

  • 知道瀏覽器、HTML、CSS、JavaScript 各自負責什麼。
  • 理解使用者開啟 GitHub Pages 網站時，大致發生哪些事。
  • 知道為什麼這個網站可以不用後端伺服器，也能保存部分設定。
  • 分辨前端網站、後端服務和外部線上編輯器。

一、網站是怎麼組成的？

🧱 HTML：內容與結構

定義標題、段落、連結、按鈕、表格與表單，就像房子的骨架。

🎨 CSS：外觀與排版

控制顏色、字體、間距、響應式版面與動畫，就像室內設計。

⚙️ JavaScript：互動與邏輯

處理按鈕點擊、題目判斷、主題切換與學習紀錄，就像控制系統。

二、瀏覽器如何顯示網頁？

  1. 你輸入網址或點擊連結。
  2. 瀏覽器向網站主機請求 HTML、CSS、JavaScript 和圖片等檔案。
  3. 瀏覽器解析 HTML 建立頁面結構，再套用 CSS 樣式。
  4. JavaScript 執行互動功能，例如顯示題目、切換主題和更新進度。
注意：HTML、CSS、JavaScript 通常會送到使用者的瀏覽器。因此，放在前端程式碼裡的密碼、API 金鑰或私密資料，不能當成真正的秘密。

三、這個 CodeBase 網站怎麼運作？

  • index.html 是首頁，負責展示課程入口、每日一題與新單元入口。
  • shared/style.css 管理各頁共用的顏色、版面、手機排版與動畫。
  • shared/app.js 管理深淺色模式、導覽列、每日一題及進度等互動。
  • python/ 與 cpp/ 放各語言的教學頁和練習題。
  • 其他 HTML 頁面是獨立單元；側邊選單的連結讓你在頁面間移動。

常見操作的簡化範例

// 按鈕被點擊時，更新頁面文字
const button = document.querySelector("#helloButton");
const output = document.querySelector("#output");

button.addEventListener("click", () => {
  output.textContent = "你好，世界！";
});

這段程式的意思是：先找到按鈕和文字區域，再在使用者點擊按鈕時更改文字。實際網站會有更多防呆與樣式。

四、GitHub Pages 是什麼？

GitHub Pages 可以把 repository 裡的靜態網站檔案發布成網站。它適合 HTML、CSS、JavaScript 教學網站、作品集與文件網站；但它不會自動替你執行 Python 或 C++ 後端程式。

  1. 將網站檔案放在 repository 根目錄。
  2. 在 GitHub 的 Settings → Pages 設定來源分支與資料夾。
  3. 等待發布完成，再用 Pages 網址測試首頁和內部連結。
  4. 每次更新檔案並推送到設定的分支後，網站就會重新發布。

五、為什麼每日一題和主題設定能被記住？

這個網站使用瀏覽器的 localStorage 儲存部分資料，例如主題偏好、每日一題的作答狀態與學習進度。資料通常只留在目前瀏覽器和裝置，不會自動同步到另一台電腦；清除網站資料也可能使它消失。

// 儲存一個簡單設定
localStorage.setItem("favoriteLanguage", "Python");

// 讀取設定
const language = localStorage.getItem("favoriteLanguage");

六、前端、後端與外部工具的差別

部分 常見工作 本網站的例子

動手練習

  1. 在瀏覽器開啟 CodeBase，試著切換深色與淺色模式，再重新整理頁面。
  2. 打開瀏覽器開發者工具（通常按 F12），查看 Elements 中的 HTML 與 Styles 中的 CSS。
  3. 在 Sources 或 Network 面板中找出 shared/app.js 與 shared/style.css。
  4. 思考：如果要讓每日一題在不同裝置間同步，為什麼只用 localStorage 不夠？
查看參考答案

主題設定可由 localStorage 保存，因此同一瀏覽器重新整理後仍可能保留。Elements / Styles 可以觀察 HTML 和 CSS。不同裝置無法直接共享各自的 localStorage；若要跨裝置同步，通常需要帳號系統與後端資料服務。
