一步一步拆解密碼鎖

這份教學完全在瀏覽器中操作。你不需要會寫程式、不需要安裝 Python，也不需要下載破解軟體。每個按鈕都會在頁面上直接顯示結果。

練習範圍：以下互動只使用本頁預先設定的虛構範例，以及 CodeBase 自己的封存終端機。不要輸入真正使用中的密碼，也不要拿這些步驟嘗試登入他人的帳號或網站。

你需要什麼？

  • Chrome 或 Edge 瀏覽器：查看教學頁與執行互動範例。
  • 不需要安裝其他程式：雜湊運算由瀏覽器內建的 Web Crypto API 執行。
  • 若要看程式碼：本頁會提供一小段 JavaScript 範例，並用白話文逐行解釋。

1先看懂密碼鎖怎麼判斷

  1. 點開 封存終端機挑戰。
  2. 在頁面空白處按滑鼠右鍵，選「檢視網頁原始碼」；也可以按 Ctrl + U。
  3. 在原始碼頁面按 Ctrl + F，搜尋 expectedHash 或 gateForm。
  4. 你會看到瀏覽器把輸入內容算成雜湊，再和預先設定的值比較。
你可以從哪一行看出驗證目標？

在封存終端機的原始碼中搜尋 expectedHash，會看到這一行：

const expectedHash='7b76fd0b3eb9982fd8d18a54c57f3fd9cb22f7316a30f8d6b7cae3f89909cd3a';

這一行放的是「預期 SHA-256 雜湊值」，不是直接可讀的密碼。接著搜尋 if(hash===expectedHash)，它表示：如果輸入文字算出的雜湊與預期值相同，就顯示驗證成功。

本練習的虛構答案可在本頁最後的解答提示中核對。重點是看懂「輸入 → 計算雜湊 → 比較結果」的流程，而不是把雜湊誤當成可直接解密的文字。

我看不懂程式碼，怎麼辦？

可以先把 if 想成「如果……就……」。例如 if (輸入結果相同) 的意思就是：「如果兩個結果完全相同，就顯示成功。」這一課先理解流程，不需要背語法。

2互動看看：文字會變成什麼雜湊？

SHA-256 會將任意文字轉成固定長度的十六進位字串。它不是一般加密，沒有一把鑰匙可以直接把雜湊還原成原文。請輸入本頁提供的虛構測試文字，看看結果如何。



按下按鈕後，雜湊結果會顯示在這裡。

請勿在這裡輸入真實密碼。此範例會在目前瀏覽器中計算，不會把內容送到網站伺服器。

這個按鈕背後的 JavaScript 是什麼？ 
const bytes = new TextEncoder().encode(text);
const digest = await crypto.subtle.digest("SHA-256", bytes);
const hex = [...new Uint8Array(digest)]
  .map(byte => byte.toString(16).padStart(2, "0"))
  .join("");
  • TextEncoder：把文字轉成電腦可處理的位元組。
  • crypto.subtle.digest：請瀏覽器計算 SHA-256。
  • toString(16)：把每個位元組轉成十六進位文字。
  • join("")：把所有片段接成一整串結果。

3互動看看：候選字串比對

有些人以為雜湊可以直接「解密」。實際上，常見的基本概念是猜一個候選字串、計算它的雜湊，再比較結果是否相同。下面用一份很短、固定的虛構清單示範，不會連接網站或嘗試登入。

教學目標：本頁內部預先設定的虛構字串 cat123。

候選清單： apple、hello123、cat123、dragon

按下按鈕後，會逐一顯示比對過程。

你會看到程式逐一檢查清單，直到找到相符項目。這不是直接破解任意密碼：範例的目標和候選清單都很小，而且是為教學特別設計的。

程式如何知道什麼時候找到了？ 
for (const candidate of candidates) {
  const candidateHash = await sha256(candidate);
  if (candidateHash === targetHash) {
    // 顯示「找到相符項目」
    break;
  }
}

for 代表依序處理清單中的每個項目；if 代表檢查條件；break 代表找到後停止。這裡只示範本頁的固定清單。

4試著自己檢查封存終端機

  1. 打開 封存終端機挑戰。
  2. 使用瀏覽器的「檢視網頁原始碼」。
  3. 搜尋 expectedHash，找到預期雜湊值那一行；它不是明文密碼。
  4. 搜尋 sha256，查看輸入文字怎麼被轉成雜湊。
  5. 最後找出比較條件，確認成功或失敗是怎麼決定的。

這個練習的重點是理解：如果網頁在訪客的瀏覽器中執行驗證程式，那段程式就可能被檢視。前端密碼鎖適合做遊戲和解謎，不適合保護真正的機密資料。

重要觀念：雜湊不是解密。弱密碼可能因為容易猜測而被猜中；夠長且隨機的密碼則會難得多。真正的網站應在伺服器端做權限驗證，並使用適當的密碼雜湊方案、MFA 和嘗試次數限制。
